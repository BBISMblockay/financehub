# Dashboard report presentation

## Preflight

The monthly review exposed two presentation gaps: text returned by a live
query is clipped into table cells, and fixed-height dashboard tiles are a
poor reading/printing surface for a monthly report.

Existing sections already collapse in view mode. Existing KPI comparisons,
metric pooling, typed parameters, fullscreen, pagination and buffered saves
remain the implementation paths. No new visual type or database migration.

Call paths inspected:

- `dashboard-builder.renderInspector` → `patchConfig` →
  `runtime.rerenderWidget` → `loadWidget` → `renderBody` → `tableHtml`.
  `visual_config` persists through the existing widget upsert. `tableHtml`
  also renders Report Builder previews; the new layout is opt-in.
- `tableRows` selects rows for both table/summary and CSV. Pagination and
  filter changes remain in the runtime, keyed by resolved SQL.
- `dashboard.html.setMode`, density, fullscreen, refresh and slicers share
  one runtime. Report view changes DOM/CSS only; GridStack nodes remain the
  source of saved geometry. Edit wins over `view=report` on a conflicting URL.
- `compact` also formats axes and donut totals: the negative-currency fix
  keeps magnitude, precision and units unchanged.

No workflow inputs, database policies, grants, RPC definitions, sync logic,
or destructive operations change. Existing buffered-save partial failure
handling stays intact. Report view never writes or executes new queries;
refresh still uses the existing retry/cache lifecycle. Printing shows loaded
rows only, keeping cap, filter, failure and missing-data notes visible.

Checks defined before implementation: full text and escaped values; null
versus zero; table/summary/CSV row selection; default tables unchanged;
summary settings survive save/reload; filters reach the same RPC; no layout
or data write on report entry/exit/print; mobile and print overflow.

Live assumptions: no new schema support is needed (`visual_config` is
already JSON). Production rollout still needs a smoke check of the monthly
review after merge. Local tests use the real page and runtime with the
existing stubbed Supabase harness, not production credentials.

## Use

1. Edit a table widget → Visual → Reading layout → Summary.
2. Choose a card heading (for example, Focus). Choose visible fields in
   Format (for example, Result and Next step). Text is read from the current
   query result, never inferred or generated by the layout.
3. Keep the existing section headings to organize the dashboard.
4. Click Report view for a flowing reading layout, or share the dashboard
   URL with `view=report`. Access permissions are unchanged.
5. Print / PDF prints the current loaded results. It does not fetch remaining
   pages or regenerate saved AI answers. Review the visible coverage notes.

KPI Format also accepts a comparison label such as Previous month. Authors
must match it to the report's actual comparison period; it changes words,
not calculations. Empty keeps the report column's label.

The monthly review's saved widgets are not rewritten by deploying this PR.
Its owner can opt the summary tile into Summary after merging and use the
report link. Existing dashboards keep their layout and visual defaults.

## Verification

The full existing v3 run plus the initial new suites passed (27 suites).
The additional monthly-review suite passed with synthetic financial data,
including July/August result changes, long caveats, three headline cards,
collapsed sections during printing and a phone/desktop round trip. A final
targeted rerun covers the later print/answer-note styling changes.

Mutation checks deliberately removed summary rendering, restored the old
negative-currency format, disabled the flowing layout and broke print-mode
restoration. Each now fails a test. The first layout mutation exposed a
test gap; explicit flow/overflow assertions were added before rerunning it.
No production report settings or data were changed during these tests.
