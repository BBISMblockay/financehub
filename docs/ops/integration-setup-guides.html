Shopify — store-owned app (recommended)

Setup guide · About 10 minutes

Connect a Shopify store with its own app

You create a small private app in Shopify, give it read-only access, and paste its Client ID and Client secret into SILO. SILO never sees your Shopify password.

Before you start
  • The store owner login (or a staff account allowed to develop apps)
  • The store's .myshopify.com address
  1. 1
    Find the store's Shopify address
    Open the store's Shopify admin. The address bar reads admin.shopify.com/store/your-store/… — the store address is your-store.myshopify.com. It often differs from the store's public name.
  2. 2
    Open Shopify's Dev Dashboard
    Sign in with the same account that owns the store. The app must be created in the store's own Shopify organization — an app made under a different organization is refused when SILO asks for access.

    Open Dev Dashboard https://dev.shopify.com/dashboard

  3. 3
    Create an app
    Choose Create app and name it anything (e.g. SILO).
  4. 4
    Give it read-only access, then release
    Create a new version of the app. Under access scopes, add each of these, then Release the version. All are read-only; SILO cannot change anything in your store.
    read_ordersread_productsread_inventoryread_locationsread_shopify_payments_payoutsread_draft_ordersread_reportsread_publicationsread_all_orders

    Copy all scopes read_orders,read_products,read_inventory,read_locations,read_shopify_payments_payouts,read_draft_orders,read_reports,read_publications,read_all_orders

    Don't skip read_all_orders. Without it Shopify only returns the last 60 days of orders, so SILO cannot import your sales history. If Shopify asks you to request access to it, submit the request before releasing.
  5. 5
    Install the app on the store
    From the app's overview choose Install app and pick this store. Approve the access prompt.
  6. 6
    Copy the Client ID and Client secret
    In the app's Settings, copy the Client ID and the Client secret.
    Treat the secret like a password. SILO checks the pair with Shopify before saving and stores the secret where only SILO's servers can read it.
  7. 7
    Paste them into SILO
    In Add Shopify store, enter the store address, Client ID and Client secret, then click Connect store.
  8. 8
    Finish setup in SILO
    On the new store row: Test (confirms every scope is granted), map its locations, then switch on Nightly sync and start the history import.

If something goes wrong

Shopify refused the app / "shop and app must belong to the same organization"

The app was created while signed in to a different Shopify organization. Sign in as the store owner, create the app again from the Dev Dashboard, and use the new Client ID and secret.

The store row warns about missing scopes

Add the missing scope in a new app version, release it, approve the update in the store admin if Shopify asks, then click Re-test in SILO.

The store row says order history is limited to 60 days

The app is missing read_all_orders. In the Dev Dashboard, add it to a new app version (request access if Shopify asks), release it, approve the update in the store admin, then click Re-test in SILO. Run the history import after the warning is gone — an import started without it only reaches 60 days back.

Button names on the other site can shift slightly as they update their dashboards.

In SILO: Workspace → Settings → Integrations (/v2/integrations.html).

Shopify — legacy Admin API token

Setup guide · About 3 minutes

Use an existing Shopify Admin API token

Only for stores that created a "Develop apps" custom app in their admin before 2026. Shopify no longer lets stores create new ones — use the store's own app instead if you don't already have a token.

Before you start
  • The store owner login
  • An existing custom app in the store admin
  1. 1
    Open the custom app
    In the store admin go to Settings → Apps and sales channels → Develop apps and open the existing app.
  2. 2
    Check its access
    Under Configuration, the Admin API access should include these read scopes:
    read_ordersread_productsread_inventoryread_locationsread_shopify_payments_payoutsread_draft_ordersread_reportsread_publications
  3. 3
    Copy the Admin API access token
    Under API credentials, the token starts with shpat_. Shopify shows it only once; if it was never saved, it cannot be revealed again — use the store's own app route instead.
  4. 4
    Paste it into SILO
    In Add Shopify store, enter the store address, open Already have an Admin API token?, paste it and click Save token. Then Test the row.

If something goes wrong

"Develop apps" is missing from the admin

The store has no legacy custom app and can no longer create one. Use Connect with your store's own app.

In SILO: Workspace → Settings → Integrations (/v2/integrations.html).

Meta Ads — system user token

Setup guide · About 15 minutes

Connect Meta Ads with a System User token

Meta splits this across two sites: create/register a Business app once, then do everything else in Business settings → System users (create user, assign assets, generate token) without leaving that screen.

Before you start
  • Admin access to the Meta Business portfolio that owns the ad account
  • After each link opens, confirm the correct business portfolio is selected (top-left on Business settings)
  • A Meta app of type Business linked to that portfolio (step 1 — Meta requires this before system users)
  1. 1
    Register a Business app on the portfolio
    A — Create (only if you have no app yet): In Meta for Developers, Create app → type Business → connect it to the same Business portfolio that owns your ad account.

    B — Add it to the portfolio (required either way): In Business settings go to Accounts → Apps → Add, and connect the app. SILO needs the app to appear here before a system user can generate a token.

    Meta for Developers (create app) https://developers.facebook.com/apps

    Business settings → Apps https://business.facebook.com/settings/apps

    If the app already shows under Accounts → Apps, skip A and continue to step 2.
  2. 2
    Open System users (your home base for the rest)
    Go to Users → System users in the left sidebar. The next three steps all happen on the same system user record — you should not need another Meta product tab until you paste the token into SILO.

    Open System users https://business.facebook.com/settings/system-users

    Business settings home https://business.facebook.com/settings

    Pick the correct business portfolio in the top-left if Meta prompts you.
  3. 3
    Create the system user
    Click Add new system user (or Add), name it SILO, and create it. Meta’s Admin system user role is fine for setup.
  4. 4
    Assign the app and ad account (same user)
    With SILO selected, use Assign assets (or Add assets / the ⋯ menu) twice:
    • Apps → your Business app → enable Develop app (or full app access). Without this, token generation will not list the app.
    • Ad accounts → each account SILO should report → View performance (read) access.

    Meta’s official walkthrough https://www.facebook.com/business/help/503306463479099

  5. 5
    Generate and copy the token
    Still on that system user, choose Generate new token → select the Business app from step 1 → expiration Never → tick:
    ads_readbusiness_management
    Want organic Instagram and Facebook Page reporting too? Also tick the permissions in "Optional: organic insights" below before generating. Meta shows the token (starts with EAA) once — copy it before closing the dialog.
  6. 6
    Paste it into SILO
    Click Add Meta Ads token… (or Replace token on an existing row), paste the token, and save. Leave the ad account ID blank if unsure — Test lists accounts the token can see. Then switch on Nightly sync.

Optional: organic insights (Instagram posts, Facebook Page)

  1. 7
    Add four permissions to the token
    Regenerate the token with these added alongside the two above:
    pages_show_listpages_read_engagementinstagram_basicinstagram_manage_insights
  2. 8
    Assign the Page to the system user
    Back in Business settings → Users → System users, open the same SILO user → Assign assets → Pages → your Page with at least Analyst access. Token permissions alone do not grant Page access.

    Open System users https://business.facebook.com/settings/system-users

  3. 9
    Link Instagram to the Page
    The Instagram professional account must be linked to that Facebook Page.
  4. 10
    Fill in the two IDs
    Click Test on the Meta row — it lists the Pages the token can see with their linked Instagram account. Enter the Facebook Page ID and Instagram Business Account ID on the row.

If something goes wrong

I regenerated the token — where does the new one go?

Use Replace token on the existing Meta row. Do not use Add Meta Ads token again; that creates a second connection for the same account.

Test lists no ad accounts

The ad account is not assigned to the system user (step 4), or the token was generated without ads_read.

Generate token does not list my app

The app is missing under Accounts → Apps (step 1B), or the system user does not have Develop app on that app (step 4).

Links open the wrong business

Use the portfolio picker (top-left in Business settings) before continuing. Every deep link keeps you in Business settings once signed in.

"Could not derive a Page access token" / error #190

The Page isn't assigned to the system user. Assign it (organic step 2); no new token is needed.

Redo — returns & marketing

Setup guide · About 5 minutes

Connect Redo returns and marketing

Redo pushes every return to SILO through a webhook you add in Redo. An optional API token adds campaign and automation reporting.

Before you start
  • Admin access to your Redo merchant dashboard
  1. 1
    Create the connection in SILO
    Click Connect Redo…. SILO creates a webhook URL and a secret just for your company and shows them on the Redo row.
  2. 2
    Add a webhook in Redo
    In Redo's merchant dashboard, add a webhook subscription:
    • URL — the webhook URL from SILO
    • Event — Return event (all statuses)
    • Auth secret — the webhook secret from SILO (use its Copy button)
    If you ever click Regenerate on the secret in SILO, paste the new one into Redo too, or deliveries stop.
  3. 3
    Optional: API token for marketing reporting
    In Redo's merchant admin, open the API settings and create a token with these read scopes, then paste it into the API secret field on the Redo row:
    CampaignsMarketing automationsCampaign analyticsMarketing automation analyticsMarketing templates
  4. 4
    Check it's working
    Last event on the Redo row updates on the next return status change. Redo may also resend recent returns right after the webhook is added.

If something goes wrong

Last event never updates

The URL or secret in Redo doesn't match SILO's. Copy both again from the Redo row.

Marketing numbers are missing

The API token is missing the marketing read scopes; the nightly records the sync as skipped. Create a token with all five scopes and paste it in.
